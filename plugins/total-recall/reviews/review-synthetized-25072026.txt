 REMAINS — PHASE 6: SERVER / TOOLS API SURFACE
================================================================================
 Split: 6.1-6.3 = the BIG McpServer migration (dedicated branch, both plans
 agree: branch → migrate → schema-parity tests → green → merge, NOT on main
 incrementally). 6.4-6.10 = SEVEN small independent fixes that do NOT depend
 on the migration and can land on main now. Do 6.4-6.10 first (quick wins,
 each one pre-commit cycle), then attempt 6.1-6.3 on a branch.

 ── 6.1-6.3  McpServer migration (DEDICATED BRANCH, large) ──
 6.1  Migrate deprecated low-level Server class → McpServer + registerTool.
      src/server.ts still uses the deprecated setRequestHandler form (verified:
      server.ts:281+ wires tools via a `tools: { name: handler }` map passed to
      the low-level Server, not registerTool). Enables Zod boundary validation.
      Branch-only; add before/after tools/list schema-parity integration tests
      (Zod→JSON-Schema can subtly shift default/minimum/maximum rendering).
 6.2  No schema enforcement at the dispatch boundary — handlers are
      (args: any) => any with ad-hoc coercion (root cause of the T3 scalar-tags
      class). Lands with 6.1 (Zod shapes reject malformed calls uniformly).
 6.3  Co-locate the 17 tool schemas with their handlers — monolithic server.ts
      holds all schemas; export register(server) per tools/*.ts. Lands with 6.1.

 ── 6.4-6.10  Small independent fixes (land on main, no migration needed) ──
 6.4  import_memories classifies skips by regex-matching error text.
      REMAINS: src/tools/bulk.ts:83 `/already exists/.test(e.message)`.
      FIX: throw a typed MemoryExistsError (or structured {status:'exists'}) and
      branch on type, not on English error-string match.
 6.5  store_memory schema omits key/created/updated/sessions the handler accepts.
      REMAINS: handler accepts them (store.ts:46 explicitKey, :282 explicitCreated,
      :283 explicitUpdated) but server.ts store_memory schema (server.ts:57-69)
      does NOT declare key/created/updated/sessions → undocumented params override
      key derivation and timestamps. FIX: declare them in the schema (noting
      import round-trip use) OR split an internal restore path store_memory
      doesn't expose.
 6.6  rerank_memories silently truncates keys to MAX_KEYS=200; schema unbounded.
      REMAINS: cap is handler-only (rerank.ts:35,64 `MAX_KEYS=200`); server.ts
      rerank_memories schema has no maxItems. FIX: add maxItems:200 + note the
      cap in the description.
 6.7  delete_memories confirm is required AND default:false (contradictory).
      REMAINS: server.ts:138 `confirm: { type:'boolean', default:false }` while
      handler requires `args.confirm === true` (bulk.ts:109). FIX: drop the dead
      default:false (the field is effectively required).
 6.8  export_memories silently exports '' for unreadable bodies → import(force)
      can overwrite real content with ''.
      REMAINS: src/tools/bulk.ts:32 `content: content ?? ''` — a null readMemoryContent
      becomes empty string with no error signal, no errors count. FIX: on null
      read emit {key, error:'unreadable body'} (skip the content field), add an
      `errors` count to the export result, and make import skip entries carrying
      an error field.
 6.9  delete_memories rejects the whole batch on one reserved key.
      REMAINS: src/tools/bulk.ts:105 `if (keys.some(isReservedKey)) throw` aborts
      the entire batch. FIX: drop the up-front throw; let the per-key path record
      that key as an error like every other per-key failure (partial success).
 6.10 shutdown() can run twice concurrently (stdin 'end' + 'close' both fire).
      REMAINS: src/index.ts:24-42 — shutdown() has no latch; process.stdin
      'end' and 'close' can both call it. FIX: a `let shuttingDown = false` guard
      at the top of shutdown() (early-return if already set).
